- Date / Status: accepted.

### Task 4: write signature-scheme spec

`docs/spec/signature-scheme.md`. Cover:

- Scope: Ed25519 over the raw 32-byte SHA-256 of canonical-JSON of the four-field hashed map.
- Keypair file format: 32 raw bytes at `~/.provedex/keys/ed25519.key`, mode 0600 on unix.
- Signing input: explicit byte construction (re-state from canonical-json + event-schema specs).
- Signature encoding: 64 raw bytes hex-encoded into 128 ASCII chars.
- Pubkey encoding: 32 raw bytes hex-encoded into 64 ASCII chars.
- Verification algorithm: step-by-step (decode pubkey, decode sig, recompute hash, call ed25519 verify).
- Test vectors: 2-3 with fixed seed + known event + expected sig hex.
- Versioning policy.

Confidence target: a binding implementer in any language can read this and reproduce the signature byte-for-byte.

Commit: `docs(spec): signature-scheme.md normative`.

### Task 5: write ledger-format spec

`docs/spec/ledger-format.md`. Cover:

- File path: default `~/.provedex/ledger.ndjson`, override via `PROVEDEX_LEDGER`.
- Line format: one canonically-serialized SignedEvent per line, terminated by `\n` (LF). Wire JSON does NOT have to be canonical-JSON; it is ordinary serde_json output. Verification recomputes canonical-JSON for hashing.
- Append semantics: `O_APPEND | O_CREATE | O_WRONLY`, `fsync_data` after each write. Concurrent writers must serialize through a single `Ledger` instance (the Mutex<File> lives there).
- Read semantics: open read-only, scan line-by-line, skip blank lines, decode each non-blank as SignedEvent, fail on any decode error.
- Crash-recovery guarantee: a partially written line at EOF is treated as a corrupt record and read fails (the Rust impl returns LedgerError::Json). Upstream tools (verify, replay, export) surface that as a chain-broken state. No silent truncation.
- Versioning: this is v1; format change requires ADR + schema bump.

Confidence target: an operator can write a Python script that round-trips through the file format using only this spec.

Commit: `docs(spec): ledger-format.md normative`.
